# Эмулятор командной оболочки (вариант 19)

Практическая работа по дисциплине «Конфигурационное управление».
Эмулятор языка оболочки UNIX-подобной ОС с графическим интерфейсом.

## Общее описание

Программа открывает окно, в котором работает диалог в стиле командной
строки: приглашение, ввод команды, вывод результата. Заголовок окна
строится по данным реальной ОС: `Эмулятор - [username@hostname]`.

Состояние этапов разработки:

| Этап | Содержание                          | Статус |
|------|-------------------------------------|--------|
| 1    | REPL, GUI, заглушки `ls`, `cd`      | готово |
| 2    | Параметры, стартовый скрипт         | готово |
| 3    | VFS из XML-файла                    | готово |
| 4    | `ls`, `cd`, `wc`, `echo`            | готово |
| 5    | `rm`, `cp`                          | готово |

## Параметры командной строки

| Параметр        | Описание                                              |
|-----------------|-------------------------------------------------------|
| `--vfs PATH`    | путь к физическому расположению VFS                   |
| `--script PATH` | путь к стартовому скрипту                             |
| `--no-gui`      | работать в терминале, без окна (для тестов и CI)      |

При запуске эмулятор выводит все заданные параметры (отладочный вывод,
строки `[debug] ...`) в окно эмулятора и в stdout реального терминала.
Незаданные параметры отображаются как `(not set)`. Неизвестный параметр
приводит к сообщению об использовании и коду завершения 2.

### Стартовый скрипт

Файл в кодировке UTF-8: одна команда эмулятора на строку.

* Пустые строки пропускаются.
* Строки, начинающиеся с `#`, — комментарии: показываются, но не
  выполняются.
* Каждая строка показывается вместе с приглашением, затем выводится
  результат — получается диалог, как при ручном вводе.
* Выполнение **останавливается на первой ошибке** (команда вернула
  ненулевой код). Выводится сообщение вида
  `script error: <файл>: line 3 failed with status 1, script stopped`.
  Эмулятор остаётся в интерактивном режиме, код завершения процесса — 1.
* Если скрипт не найден или не является UTF-8 текстом, выводится
  `script error: cannot read script '<файл>': ...`.
* Команда `exit` в скрипте завершает эмулятор.

## Виртуальная файловая система (VFS)

Источник VFS — XML-файл (параметр `--vfs`). Все операции выполняются
**в памяти**: файл только читается, на диск ничего не распаковывается
и не записывается. Без параметра `--vfs` используется пустая VFS
(только корневой каталог `/`).

Формат файла:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs>
  <file name="hello.txt">Hello, world!
</file>
  <dir name="docs">
    <file name="empty.txt"/>
    <file name="data.bin" encoding="base64">AAECAwQFBgcICQoLDA0ODw==</file>
  </dir>
</vfs>
```

* корневой элемент `<vfs>` — корневой каталог `/`;
* `<dir name="...">` — каталог, внутри которого могут быть `<dir>` и
  `<file>`;
* `<file name="...">` — файл; текст внутри элемента — содержимое в
  UTF-8 (как есть, включая переводы строк);
* `encoding="base64"` — содержимое двоичное, закодировано в base64
  (пробелы и переводы строк внутри игнорируются); `encoding="text"` —
  значение по умолчанию;
* имя обязательно, не может быть `.` и `..`, содержать `/` и пробельные
  символы (иначе его нельзя набрать в командной строке), имена внутри
  одного каталога уникальны.

Примеры: `examples/vfs/minimal.xml` (пустая VFS),
`several_files.xml` (несколько файлов, в том числе двоичный и
с русским текстом), `deep.xml` (6 уровней каталогов и файлов).

### Ошибки загрузки VFS

Сообщение имеет вид `vfs error: cannot load VFS '<путь>': <причина>`:

| Ситуация                    | Причина в сообщении                       |
|-----------------------------|-------------------------------------------|
| файл не найден / это папка  | `No such file or directory`, `Is a directory` |
| не well-formed XML          | `invalid XML (...)`                       |
| неверная структура          | `invalid format: ...` (см. список ниже)   |

К неверной структуре относятся: неверный корневой элемент, неизвестный
элемент, отсутствие имени, недопустимое имя, дубликат имени, ошибочные
base64 или `encoding`.

После ошибки эмулятор продолжает работать с пустой VFS, код завершения
процесса — 1. Стартовый скрипт в этом случае **не запускается**
(`script error: startup script skipped, the VFS was not loaded`), так
как его команды рассчитаны на загруженную VFS.

### Служебные команды

| Команда    | Описание                                                    |
|------------|-------------------------------------------------------------|
| `vfs-info` | источник, число каталогов и файлов, общий размер, глубина   |
| `vfs-tree` | вся VFS в виде дерева (у файлов указан размер в байтах)     |

## Описание функций

### Парсер

Строка ввода делится на слова по пробельным символам: первое слово —
имя команды, остальные — аргументы. Кавычек и подстановок нет.
Пустая строка игнорируется.

### Ошибки

* неизвестная команда: `foo: command not found` (код 127);
* неверные аргументы: например, `cd: too many arguments` (код 1).

Сообщения об ошибках выделяются в окне красным цветом.

### Команды

| Команда                  | Поведение                                   |
|--------------------------|---------------------------------------------|
| `ls [-a] [-l] [путь...]` | список файлов и каталогов VFS               |
| `cd [путь]`              | смена текущего каталога                     |
| `wc [-l] [-w] [-c] файл...` | строки, слова, байты файлов VFS          |
| `echo [арг...]`          | печатает аргументы через пробел             |
| `rm [-r] [-f] путь...`   | удаляет файлы и каталоги (только в памяти)  |
| `cp [-r] источник... назначение` | копирует файлы и каталоги (в памяти) |
| `exit`                   | закрывает окно эмулятора                    |
| `vfs-info`               | служебная: сведения о загруженной VFS       |
| `vfs-tree`               | служебная: дерево VFS                       |

Пути могут быть абсолютными (`/home/user`) и относительными
(`docs/../notes.txt`); `.` и `..` поддерживаются, `..` корня — это
корень. Имена с пробелами невозможны (парсер делит строку по пробелам).

#### ls

* без аргументов выводит текущий каталог, по одному имени в строке,
  в алфавитном порядке; имена, начинающиеся с `.`, скрыты;
* `-a` показывает скрытые имена, а также `.` и `..`;
* `-l` — длинный формат: тип (`d` каталог, `-` файл), размер в байтах,
  имя (`- 18 notes.txt`);
* опции можно объединять (`-la`); `--` завершает список опций;
* несколько операндов: сначала файлы, затем каталоги с заголовками
  `путь:`, блоки разделены пустой строкой;
* ошибки: `ls: cannot access 'x': No such file or directory`,
  `ls: invalid option -- 'x'`. Остальные операнды при этом выводятся.

#### cd

* без аргументов — переход в корень `/` (домашнего каталога в VFS нет);
* ошибки: `cd: x: No such file or directory`, `cd: x: Not a directory`,
  `cd: too many arguments`.

#### wc

* по умолчанию выводит строки, слова и байты; `-l`, `-w`, `-c` выбирают
  счётчики (порядок вывода всегда строки, слова, байты);
* для нескольких файлов добавляется строка `total`;
* считаются байты, а не символы (двоичные файлы из base64 работают так же);
* ошибки: `wc: missing file operand` (stdin нет), `wc: x: Is a directory`,
  `wc: x: No such file or directory`; остальные файлы всё равно считаются.

#### echo

Печатает аргументы через один пробел; без аргументов — пустая строка.
Опций нет (`echo -n x` печатает `-n x`).

#### rm

Изменяет только VFS в памяти, XML-файл на диске не меняется.

* файл удаляется без опций; каталог — только с `-r` (или `-R`), вместе
  со всем содержимым;
* `-f` не сообщает об отсутствующих путях и о пустом списке операндов;
* ошибка одного операнда не мешает обработать остальные;
* ошибки: `rm: missing operand`, `rm: cannot remove 'x': No such file
  or directory`, `... Is a directory`, `rm: invalid option -- 'x'`;
* защита: корень (`rm: it is dangerous to operate recursively on '/'`),
  `.` и `..` (`rm: refusing to remove '.' or '..' directory: ...`) и
  текущий каталог вместе с его родителями
  (`rm: cannot remove 'x': Device or resource busy`) не удаляются.

#### cp

Копии создаются только в памяти и не зависят от оригиналов.

* `cp файл новое_имя` — копия под новым именем (существующий файл
  перезаписывается);
* `cp файл каталог` и `cp файл1 файл2 ... каталог` — копии внутрь каталога
  под прежними именами; несколько источников требуют каталог в качестве
  назначения;
* каталоги копируются только с `-r` (или `-R`), рекурсивно; если в
  целевом каталоге уже есть каталог с таким именем, он заменяется копией;
* ошибки: `cp: missing file operand`,
  `cp: missing destination file operand after 'x'`,
  `cp: cannot stat 'x': No such file or directory`,
  `cp: cannot create regular file 'x': No such file or directory`,
  `cp: -r not specified; omitting directory 'x'`,
  `cp: 'a' and 'b' are the same file`,
  `cp: cannot copy a directory, 'a', into itself, 'b'`,
  `cp: cannot overwrite directory 'x' with non-directory`,
  `cp: cannot overwrite non-directory 'x' with directory 'y'`,
  `cp: target 'x' is not a directory`,
  `cp: invalid option -- 'x'`; остальные источники всё равно копируются.

Приглашение имеет вид `user@host:<текущий каталог VFS>$`.

### Интерфейс

* поле ввода внизу окна, `Enter` — выполнить строку;
* `↑` / `↓` — перебор истории введённых команд.

## Сборка, запуск и тесты

Требуется Python 3.10+ с модулем `tkinter`. Внешних зависимостей нет.

```bash
./run.sh            # или: make run
make test           # модульные тесты (GUI-тесты пропускаются без дисплея)
make test-scripts   # скрипты реальной ОС из tests/scripts
make check          # всё вместе
```

Для GUI-тестов на машине без дисплея: `xvfb-run -a make check`.
Переменная `PYTHON` выбирает интерпретатор: `PYTHON=python3.12 make test`.

### Скрипты реальной ОС

Каждый скрипт в `tests/scripts/` запускает эмулятор (`run.sh`) с
некоторым набором параметров и проверяет вывод и код завершения:

| Скрипт                         | Что проверяет                           |
|--------------------------------|-----------------------------------------|
| `test_params_none.sh`          | запуск без параметров                   |
| `test_param_script.sh`         | `--script`, диалог из скрипта           |
| `test_param_script_error.sh`   | остановка скрипта на первой ошибке      |
| `test_param_script_missing.sh` | отсутствующий файл скрипта              |
| `test_param_vfs.sh`            | `--vfs`                                 |
| `test_params_all.sh`           | все параметры вместе                    |
| `test_params_invalid.sh`       | неизвестный параметр                    |
| `test_gui_smoke.sh`            | запуск окна и выход по `exit` в скрипте |
| `test_vfs_minimal.sh`          | минимальная VFS                         |
| `test_vfs_several_files.sh`    | несколько файлов, base64                |
| `test_vfs_deep.sh`             | 6 уровней каталогов и файлов            |
| `test_vfs_errors.sh`           | все виды ошибок загрузки VFS            |
| `test_stage3_all.sh`           | стартовый скрипт `stage3_all.emu`       |
| `test_stage4_commands.sh`      | скрипт `stage4_commands.emu` (все режимы) |
| `test_stage4_errors.sh`        | ошибки `ls`, `cd`, `wc`                 |
| `test_stage5_commands.sh`      | скрипт `stage5_commands.emu` (rm, cp)   |
| `test_stage5_errors.sh`        | ошибки `rm`, `cp`, XML не меняется      |

## Примеры использования

Запуск со стартовым скриптом (терминальный режим):

```
$ ./run.sh --no-gui --script examples/startup/stage2_error.emu
[debug] parameters:
[debug]   vfs    = (not set)
[debug]   script = examples/startup/stage2_error.emu
[debug]   no-gui = True
user@host:/$ # Stage 2: the script stops at the first error.
user@host:/$ echo first
first
user@host:/$ cd a b
cd: too many arguments
script error: examples/startup/stage2_error.emu: line 3 failed with status 1, script stopped
```

Интерактивный сеанс с VFS (`./run.sh --vfs examples/vfs/deep.xml`):

```
user@host:/$ ls -l
d  0 bin
d  0 home
- 18 readme.txt
user@host:/$ cd home/user
user@host:/home/user$ wc notes.txt
 2  4 18 notes.txt
user@host:/home/user$ echo done
done
user@host:/home/user$ cd nosuch
cd: nosuch: No such file or directory
user@host:/home/user$ foo
foo: command not found
user@host:/home/user$ exit
```

Изменение VFS (`rm`, `cp`), только в памяти:

```
user@host:/$ cp -r home/user/docs /docs2
user@host:/$ ls /docs2
drafts
report.txt
user@host:/$ rm -r home
user@host:/$ rm bin
rm: cannot remove 'bin': Is a directory
user@host:/$ cp readme.txt readme.txt
cp: 'readme.txt' and 'readme.txt' are the same file
user@host:/$ exit
```
