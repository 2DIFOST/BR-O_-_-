# Эмулятор командной оболочки (вариант 19)

Практическая работа по дисциплине «Конфигурационное управление».
Эмулятор языка оболочки UNIX-подобной ОС с графическим интерфейсом.

## Общее описание

Программа открывает окно, в котором работает диалог в стиле командной
строки: приглашение, ввод команды, вывод результата. Заголовок окна
строится по данным реальной ОС: `Эмулятор - [username@hostname]`.

Состояние этапов разработки:

| Этап | Содержание                          | Статус |
|------|-------------------------------------|--------|
| 1    | REPL, GUI, заглушки `ls`, `cd`      | готово |
| 2    | Параметры, стартовый скрипт         | готово |

## Структура проекта

```
src/shellemu/        исходный код
    cli.py           точка входа, запуск GUI или консоли
    config.py        параметры командной строки, отладочный вывод
    session.py       диалог: выполнение строк и стартовых скриптов
    script.py        чтение стартовых скриптов
    console.py       терминальный режим (--no-gui)
    errors.py        исключения эмулятора
    gui.py           графический интерфейс (tkinter)
    shell.py         ядро: разбор и выполнение команд (без GUI)
    parser.py        разбиение строки на команду и аргументы
    response.py      результат выполнения команды
    history.py       история ввода (клавиши «вверх»/«вниз»)
    sysinfo.py       данные реальной ОС (пользователь, хост)
    commands/        реализации команд
examples/startup/    примеры стартовых скриптов эмулятора (*.emu)
tests/               модульные тесты
tests/scripts/       скрипты реальной ОС (sh), вызывающие эмулятор
run.sh, Makefile     запуск и сборка
```

## Параметры командной строки

| Параметр        | Описание                                              |
|-----------------|-------------------------------------------------------|
| `--vfs PATH`    | путь к физическому расположению VFS                   |
| `--script PATH` | путь к стартовому скрипту                             |
| `--no-gui`      | работать в терминале, без окна (для тестов и CI)      |

При запуске эмулятор выводит все заданные параметры (отладочный вывод,
строки `[debug] ...`) в окно эмулятора и в stdout реального терминала.
Незаданные параметры отображаются как `(not set)`. Неизвестный параметр
приводит к сообщению об использовании и коду завершения 2.

### Стартовый скрипт

Файл в кодировке UTF-8: одна команда эмулятора на строку.

* Пустые строки пропускаются.
* Строки, начинающиеся с `#`, — комментарии: показываются, но не
  выполняются.
* Каждая строка показывается вместе с приглашением, затем выводится
  результат — получается диалог, как при ручном вводе.
* Выполнение **останавливается на первой ошибке** (команда вернула
  ненулевой код). Выводится сообщение вида
  `script error: <файл>: line 3 failed with status 1, script stopped`.
  Эмулятор остаётся в интерактивном режиме, код завершения процесса — 1.
* Если скрипт не найден или не является UTF-8 текстом, выводится
  `script error: cannot read script '<файл>': ...`.
* Команда `exit` в скрипте завершает эмулятор.

## Описание функций

### Парсер

Строка ввода делится на слова по пробельным символам: первое слово —
имя команды, остальные — аргументы. Кавычек и подстановок нет.
Пустая строка игнорируется.

### Ошибки

* неизвестная команда: `foo: command not found` (код 127);
* неверные аргументы: например, `cd: too many arguments` (код 1).

Сообщения об ошибках выделяются в окне красным цветом.

### Команды (этап 1)

| Команда          | Поведение                                           |
|------------------|-----------------------------------------------------|
| `ls [арг...]`    | заглушка: печатает своё имя и аргументы             |
| `cd [арг]`       | заглушка: печатает своё имя и аргумент              |
| `exit`           | закрывает окно эмулятора                            |

### Интерфейс

* поле ввода внизу окна, `Enter` — выполнить строку;
* `↑` / `↓` — перебор истории введённых команд.

## Сборка, запуск и тесты

Требуется Python 3.10+ с модулем `tkinter`. Внешних зависимостей нет.

```bash
./run.sh            # или: make run
make test           # модульные тесты (GUI-тесты пропускаются без дисплея)
make test-scripts   # скрипты реальной ОС из tests/scripts
make check          # всё вместе
```

Для GUI-тестов на машине без дисплея: `xvfb-run -a make check`.
Переменная `PYTHON` выбирает интерпретатор: `PYTHON=python3.12 make test`.

### Скрипты реальной ОС

Каждый скрипт в `tests/scripts/` запускает эмулятор (`run.sh`) с
некоторым набором параметров и проверяет вывод и код завершения:

| Скрипт                         | Что проверяет                           |
|--------------------------------|-----------------------------------------|
| `test_params_none.sh`          | запуск без параметров                   |
| `test_param_script.sh`         | `--script`, диалог из скрипта           |
| `test_param_script_error.sh`   | остановка скрипта на первой ошибке      |
| `test_param_script_missing.sh` | отсутствующий файл скрипта              |
| `test_param_vfs.sh`            | `--vfs`                                 |
| `test_params_all.sh`           | все параметры вместе                    |
| `test_params_invalid.sh`       | неизвестный параметр                    |
| `test_gui_smoke.sh`            | запуск окна и выход по `exit` в скрипте |

## Примеры использования

Запуск со стартовым скриптом (терминальный режим):

```
$ ./run.sh --no-gui --script examples/startup/stage2_error.emu
[debug] parameters:
[debug]   vfs    = (not set)
[debug]   script = examples/startup/stage2_error.emu
[debug]   no-gui = True
user@host:~$ # Stage 2: the script stops at the first error.
user@host:~$ ls first
ls first
user@host:~$ cd a b
cd: too many arguments
script error: examples/startup/stage2_error.emu: line 3 failed with status 1, script stopped
```

Интерактивный сеанс:

```
user@host:~$ ls -l /tmp
ls -l /tmp
user@host:~$ cd docs
cd docs
user@host:~$ cd a b
cd: too many arguments
user@host:~$ foo
foo: command not found
user@host:~$ exit
```
